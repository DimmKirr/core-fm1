# Porting Subsystems & Modules

How firmware lineage code gets ported to core-fm1, subsystem by subsystem.

## Strategy: mock first, wire later

Every subsystem follows the same three-phase approach:

1. **Adapter contracts** - define the types and globals the subsystem reads/writes (`cfm1_*.h`)
2. **Mock data behind adapters** - populate those types with realistic defaults so dependent code compiles and renders without real hardware subsystems
3. **Wire real subsystems** - enable the Kconfig symbol, mock stubs get skipped, real implementations populate the same globals

Code ported in phase 2 never changes in phase 3. It only reads from adapter-defined types.

## Adapter layer

Adapters live in `firmware/adapters/cfm1_*.h`. Each one defines types, globals, constants, and mock data (when the real subsystem is off).

```
cfm1_audio.h    - track/song/engine types, P_* enum, mock engine + init
cfm1_engine.h   - engine_t vtable, param_desc_t (MIT licensed)
cfm1_seq.h      - seq_steps(), seq_counting() stubs
cfm1_page.h     - cfm1_page_t vtable for page abstraction
cfm1_fx.h       - effects chain stubs
cfm1_midi.h     - MIDI routing stubs
cfm1_storage.h  - project storage stubs
cfm1_mod.h      - modulation matrix stubs
```

## What the UI reads (and where it comes from)

```
UI page code           reads from          defined in
-----------           ----------          ----------
trk[song.sel]         cfm1_audio.h        mock: cfm1_mock_init()
                                          real: audio core fills trk[]
ENGINES[t->eng_req]   cfm1_audio.h        mock: _eng_mock (ANALOG)
                                          real: engines.c registry
song.bpm, .playing    cfm1_audio.h        mock: cfm1_mock_init()
                                          real: transport / sequencer
eng->edit[k].label    cfm1_engine.h       engine vtable (MIT)
t->step[i].note[0]    cfm1_audio.h        mock: pre-filled pattern
                                          real: sequencer
```

The UI never calls audio functions, never allocates voices, never touches hardware. It reads structs.

## UI

Screen rendering, event dispatch, menu system, splash screen.

Kconfig: `CONFIG_UI_FELUCCA`, `CONFIG_UI_MELODEE`, `CONFIG_UI_SLOOP`, `CONFIG_UI_CORE`.

### Components

| Component | File(s) | Description |
|-----------|---------|-------------|
| Shell | `shell.c` | Page lifecycle, navigation, splash dispatch |
| Pages | `page_*.c` | Individual screens (HOME, ENV, SEQ, ABOUT, etc.) |
| Drawing | `draw.c` | Header/card/footer layout primitives |
| Icons | `fui_icons.c` | Track cushions, icon font rendering |
| Renderer | `gfx.c` | Canvas primitives (`cv_begin`, `cv_blit`, `cv_text_*`) |
| Boot logo | `ui/core/boot_logo.c` | RLE-compressed logo decoder, shared across all UI lineages |
| Splash | Kconfig `SPLASH_LOGO` / `SPLASH_NONE` | Selectable splash screen style |

### Boot logo component

`boot_logo.c` decodes the RLE-compressed RGB565 logo from `build/gen/boot_logo.h` (generated by `tools/logo_convert.py` from `assets/logo-dark.png`).

Functions:
- `logo_draw(x, y)` - draws full 240x240 canvas (logo centered with padding rows)
- `logo_draw_content(x, y)` - draws only the content rows (64px tall), skipping padding

The early boot screen (`fm1_main`) calls `logo_draw(0, 0)` right after `lcd_init()`. This is the earliest possible display point: the boot stub and loader run before LCD initialization.

### Splash screen (Kconfig choice)

The splash is a Kconfig choice under UI:
- `CONFIG_SPLASH_LOGO` (default) - centered logo + version string below
- `CONFIG_SPLASH_NONE` - skip splash, go straight to home page

The Felucca splash renders the logo via `logo_draw_content()` centered vertically, with the version in `AF_S` font below it. Duration: 1s (10 main loop frames at 100ms each).

New splash styles can be added as Kconfig options (e.g. animated splash).

### Felucca UI port (worked example)

#### 1. Upstream renderer (gfx.c)

The Felucca canvas renderer was included as-is from the upstream subtree. It provides:

- `cv_begin` / `cv_blit` / `cv_rrect` / `cv_text_*` - drawing primitives
- `palette_set()` and `ux.*` theme tokens (`T_BG`, `T_SURF`, `T_THEME`, etc.)
- Anti-aliased fonts (`AF_S` 12px, `AF_M` 15px, `AF_L` 28px)

Generated headers (`ui_fonts.h`, `ui_icons.h`, `ui_keycaps.h`, `ui_palettes.h`) are built by Python generators when `GEN_FELUCCA_UI` is selected.

#### 2. Icon rendering (fui_icons.c)

Upstream `icons.c` has label-lookup functions (`param_icon()`, `mod_src_icon()`) that depend on the full Felucca firmware. We extracted only the rendering functions into `fui_icons.c`:

- `cv_trk()` - numbered track cushion
- `cv_icon_on()` / `cv_icon_in()` / `cv_icon_mid()` - icon font rendering
- `trk_icon()` - icon ID for track number

#### 3. Drawing primitives (draw.c)

`fui_draw_head()`, `fui_draw_card()`, `fui_draw_foot()` replicate Felucca's visual layout:

- **Header**: track cushion, stop/play icon, BPM (centred), battery (right)
- **Card**: `[icon] LABEL` (S font), `VALUE unit` (M + S font, same baseline), gauge bar
- **Footer**: engine icon + name (left), preset name (middle), page title (right)

#### 4. Shell navigation (shell.c)

`fsh_init()` / `fsh_register()` / `fsh_draw()` manage page lifecycle. Button-to-page mapping (HOME, FX, SCL, etc.) and long-press HOME for ABOUT. On init, `cfm1_mock_init()` is called when `CONFIG_AUDIO` is off.

#### 5. Pages

Each page is a `cfm1_page_t` with `.draw`, `.knob`, `.button`, `.key` callbacks:

- `page_home.c` - 4 engine knob cards + waveform + track overview
- `page_params.c` - ENV, LFO, FX, SCL, EDIT, ARP, VOICE (generic 4-card layout)
- `page_seq.c` - step grid
- `page_mixer.c` - 4 level cards + vertical bars
- `page_about.c` - firmware info

#### 6. Build configuration

`configs/felucca_mock_defconfig`:
```
CONFIG_INPUT=y
CONFIG_UI_FELUCCA=y
# CONFIG_AUDIO is not set
```

To wire real audio, enable `CONFIG_AUDIO=y`. The `#ifndef CONFIG_AUDIO` guard in `cfm1_audio.h` removes the mock engine and init function.

### Porting a different UI lineage

1. Include their renderer (gfx equivalent)
2. Create adapter stubs with realistic mock data
3. Write pages that read from the adapter types
4. Build with the lineage's UI Kconfig + mocked subsystems
5. Wire real subsystems one at a time

The adapter contract is the same across all lineages.

## Audio

Voice allocator, render pipeline, DMA half-buffer, mixer.

Kconfig: `CONFIG_AUDIO`. Optionally uses `CONFIG_DUAL_CORE`.

### Audio Core (pick one lineage)

- **Felucca**: 8+6 voices, fixed allocation
- **SLOOP**: voice pool shared across layers
- **Melodee**: 18 budget units, FPU-optimized render

### Engines (pick any)

Engines implement the `engine_t` vtable (defined in `cfm1_engine.h`, MIT licensed). Required fields: `note_on`, `render`. Optional: `amp`, `block`, `done`, `desc`, `keys`, `alloc`, `legato`, `mono_key`, `post`, `cap`, `units`, `preset_make`.

Engine cost is measured in VBUDGET units (Prophet: 2-3, FM6: 2, CZ-1: 1).

Engines compile independently of the full audio core via `CONFIG_ENGINES` (auto-selected). Build-time table generator (`tools/gen_engine_tables.py`) produces `fe_tables.h` with SINE, PITCH_OCT, SVF_G, and TANH_Q15 lookup tables. DSP helpers (`dsp.c`) provide fixed-point math.

Porting an engine:
1. Copy the engine source to `firmware/src/audio/engines/`
2. Copy `dsp.c` if not already present (shared DSP helpers, MIT)
3. Add Kconfig symbol `CONFIG_ENGINE_<NAME>` in `kconf/engines.kconfig` with `select ENGINES`
4. Add conditional `#include` in `engines.c`
5. Register in the `ENGINES[]` array

### NOISE engine (worked example)

The NOISE engine was ported from Felucca (MIT, 271 lines). It compiles against `cfm1_engine.h` / `cfm1_audio.h` without modification: `voice_t`, `vmod_t`, `engine_t`, and `track_t` are type-compatible.

Dependencies: `fe_tables.h` (generated), `dsp.c` (MIT helpers: `clamp`, `mulq15`, `noise32`, `softclip`, `soft_knee`, `voice_amp`), and the SVF_G cutoff table.

Config: `CONFIG_ENGINE_NOISE=y` in the defconfig. No `CONFIG_AUDIO` required: the engine renders through the adapter types and appears in the `ENGINES[]` registry for the UI.

### ANALOG engine (worked example)

The ANALOG engine was ported from Felucca (MIT, ~500 lines). Same process as NOISE: copy source to `firmware/src/audio/engines/eng_analog.c`, add `CONFIG_ENGINE_ANALOG` in `kconf/engines.kconfig`, add conditional `#include` in `engines.c`, register in `ENGINES[]`.

Dependencies: same as NOISE (`fe_tables.h`, `dsp.c`, SVF_G table). ANALOG also uses `PITCH_OCT[]` and `SINE[]` from the generated tables for its oscillator.

The engine's `.edit[]` array defines 8 parameter descriptors (CUT, RES, CUT2, KTR, OSC, SUB, PW, BND) with `.def` defaults, `.min`/`.max` ranges, `.label`, `.unit`, and `.fmt`. The `.knob[]` array maps the 4 physical encoders to parameter indices. These are read by the UI page to display labels, values, and gauge bars without any engine-specific code in the UI.

### Engine switching

Engine switching is a **UI action**, not a subsystem or module. It is triggered by the SELECT encoder on the HOME page and goes through the adapter layer.

The adapter function `cfm1_engine_select()` lives in `voice.c` and handles IRQ-safe switching:

```c
static void cfm1_engine_select(track_t *t, uint32_t ei)
{
    const engine_t *e;
    uint32_t i;
    if (ei >= NENGINES) ei = 0;
    e = ENGINES[ei];
    fm1_irq_off();
    trk_all_off(t);
    t->eng_req = (uint8_t)ei;
    t->engine  = (uint8_t)ei;
    t->preset  = 0;
    for (i = 0; i < 8u; i++)
        t->p[P_E0 + i] = e->edit[i].def;
    fm1_irq_on();
}
```

This mirrors upstream Felucca's `set_engine_of()` (`ui.c:1385`). The IRQ guard ensures the audio ISR sees either the old engine with its parameters or the new engine with its own defaults, never a half-updated state.

The UI page (`page_home.c`) calls `cfm1_engine_select(t, ei)` on encoder 0 rotation:

```c
if (id == 0 && NENGINES > 1u) {
    track_t *t = &trk[song.sel];
    int32_t e = (int32_t)t->eng_req + clicks;
    if (e < 0) e = (int32_t)NENGINES - 1;
    if (e >= (int32_t)NENGINES) e = 0;
    cfm1_engine_select(t, (uint32_t)e);
    fsh_dirty = 1;
    return 1;
}
```

This wraps the engine index, so rotating past the last engine goes back to the first. The UI page never directly writes `t->engine` or `t->eng_req`: it always goes through the adapter function.

### End-to-end audio: what we fixed wiring NOISE

Getting the NOISE engine to produce audio in the emulator required wiring four subsystems beyond the engine itself. Each fix was small, but all four were needed before any sound came out.

#### 1. Voice allocator (`audio/voice.c`)

The stub voice allocator was a no-op. Replaced with a working round-robin allocator:
- `trk_note_on`: finds a free voice (or steals the oldest), sets note/vel/gate/active/age/pitch16, calls `engine->note_on(t, v)`
- `trk_note_off`: finds matching active voice, clears gate/active
- `engine_block`: iterates active voices, calls `engine->render` into a per-voice buffer, sums into L/R mix buffers

The voice allocator renders mono per-voice, then adds to both L/R channels. The `vmod_t` passed to render must have `pitch16`, `inc` (from `pitch_inc()`), and `amp0`/`amp1` set to non-zero values or the engine output is silent.

#### 2. Audio core (`audio/core/audio.c`)

The audio core implements the I2S DMA double-buffer ISR:
- `fm1_alnk0_irq()`: checks `fm1_audio_pending()`, calls `mix_block()`, interleaves L/R into DMA buffer with `<< OUT_SHIFT` (Q15 to 24-bit)
- `audio_init()`: zeros the DMA buffer, inits tracks with `params_init()`, calls `fm1_audio_init(abuf, HALF_WORDS, isr_alnk0, 3)`

The ISR function must be non-static (external linkage) because the assembly wrapper in `fm1_isr.S` calls it by symbol.

#### 3. IRQ enable (the silent killer)

`fm1_irq_enable_all()` was never called in `core_fm1.c`. Without it, the CPU ignores all interrupts: the ALNK0 DMA ISR never fires, so the audio buffer stays zero-filled. Melodee calls this in `main.c` after all subsystems are initialized. We added it right after `audio_init()`.

This produced zero audio output with no compiler warnings, no linker errors, and no runtime crashes. The firmware ran, the LCD displayed correctly, the engine was registered, but the DMA buffer was never filled. Always check that `fm1_irq_enable_all()` is called before the main loop.

#### 4. ISR timing globals

The assembly ISR wrapper (`fm1_isr.S`) reads/writes `fm1_audio_irq_start_ticks` and `fm1_audio_irq_elapsed_ticks` for diagnostics. These must be non-static `uint32_t` globals in the C translation unit. Without them, the linker fails with undefined references.

#### 5. Adapter ordering

`cfm1_midi.h` provides a stub `midi_out_event()` guarded by `#ifndef CFM1_USB_MIDI`. The USB MIDI module (`midi/usb.c`) defines the real one. But `CFM1_USB_MIDI` was defined _after_ the adapter include, so both definitions were emitted, causing a redefinition error. Fix: define `CFM1_USB_MIDI` before the adapter includes.

#### 6. Page key handler return type

The `cfm1_page_t.key` field expects `int (*)(uint32_t, uint32_t)`. The `fhome_key` handler was declared `void`. JieLi clang 4.0.1 treats this as an error with `-Wincompatible-pointer-types`. Fix: change return type to `int`, return 1.

#### Signal chain (verified working)

```
main loop -> fm1_input_scan() -> note edge detection
  -> fsh_key(note, vel) [Felucca shell]
    -> page->key(note, vel) [fhome_key]
      -> trk_note_on(track, note, vel) [voice allocator]
        -> engine->note_on(track, voice) [NOISE]

ISR (fires every 128 samples @ 44.1kHz):
  isr_alnk0 [assembly wrapper, fm1_isr.S]
    -> fm1_alnk0_irq() [audio.c]
      -> mix_block()
        -> engine_block(track, buf_l, buf_r, n) [voice.c]
          -> engine->render(track, voice, buf, n, &vmod) [NOISE]
      -> interleave L/R into DMA buffer
      -> fm1_audio_ack_half()
```

#### E2E verification

`tests/e2e_audio_engines_test.py` verifies both engines from a **single `felucca_mock` firmware** (both `CONFIG_ENGINE_ANALOG` and `CONFIG_ENGINE_NOISE` enabled):

- **TestAnalogEngine**: boots, plays C4-G4 on the default engine (ANALOG at index 0), records WAV
- **TestNoiseEngine**: boots the same firmware, switches to NOISE via `ctrl.rotate_encoder('select', direction=1, steps=1)`, plays C4-G4, records WAV

Both tests capture audio via in-browser ScriptProcessorNode. Silence baseline RMS is 0.0. Playing RMS differs between engines (ANALOG ~0.029, NOISE ~0.084), confirming distinct synthesis.

WAV files and screenshots are saved to `tests/results/<timestamp>-e2e_audio_engines_test/`.

#### Emulator encoder timing

The fm1-emu emulator simulates quadrature encoder signals at GPIO level: `enc_state[]` cycles through GRAY code states at 2ms intervals per transition. A single encoder click produces 4 state transitions over ~8ms.

The firmware's main loop scans inputs once per frame. If the frame delay is a single `fm1_delay_ms(10)`, the firmware polls GPIO only once every ~11ms, which means it misses all intermediate quadrature states and sees only the rest position. The encoder appears to not work.

Fix: split the frame delay into 10x 1ms intervals with `fm1_input_scan()` between each:

```c
uint32_t f;
for (f = 0; f < 10u; f++) {
    fm1_delay_ms(1);
    fm1_input_scan();
}
```

This gives the quadrature decoder enough samples to detect transitions. On real hardware, the frame timing is faster and this issue does not occur.

## Boot

Startup, loader, OTA update mechanism.

### Boot chain

```
on-chip ROM -> boot stub (crt0_stub.S) -> loader (decompresses app) -> fm1_cstart
```

The boot stub (`firmware/stub/`) is the first code from flash. It initializes the CPU minimally and jumps to the loader. The loader decompresses the main application into RAM. `fm1_cstart` initializes BSS, copies data sections, and calls `fm1_main()`.

LCD is not available until `fm1_main()` calls `lcd_init()`. The boot logo appears immediately after.

### OTA

All three lineages share the M-UPGRADE SysEx protocol for USB-MIDI OTA updates. Single app area, no dual-bank.

### Lineages

- **Felucca**: stock DFU
- **SLOOP**: stock DFU
- **Melodee**: M-UPGRADE SysEx OTA, boot protection, safe-recovery

Registers and low-level hardware access. Header-only. No logic, no state.

### Common (always included)

### Porting a HAL variant

HAL files are header-only register macros. Porting means creating `fm1_<slot>_<lineage>.h` with the same function signatures as the existing variant. Kconfig radio choice selects which header gets included.
